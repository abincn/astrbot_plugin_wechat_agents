# AstrBot 内的微信任务工作台

入口在 **AstrBot 后台 → 插件 → 微信 Agent 任务 → 可视化视图 → 微信任务工作台**。
支持插件视图的后台也会在侧边栏列出该视图。不另开网页服务、不增加端口，不修改 AstrBot 的前端源码。

本页面使用 AstrBot 原生 `views/tasks/index.html` 发现机制和 `AstrBotPluginView` bridge，
后台通过 `Context.register_web_api()` 注册操作。接线参考固定 AstrBot commit
`3bebdd3918b1617c58de5a09a8b0800f8a02c4f9` 的插件视图与 `astrbot.api.web` 接口。
不支持这些接口的旧后台需先升级独立实例；本轮未实际安装或启动 AstrBot。

## 安装与准备

1. 按 [独立插件安装说明](../README.md#安装)，将 `astrbot_plugin_wechat_hook` 和
   `astrbot_plugin_wechat_agents` 分别安装到独立 AstrBot 的 `data/plugins/`。视图与 `.astrbot-plugin/` 属于 Agent 插件。
2. 沿用 [任务配置说明](../README.md#配置任务工作区)，设置 `WGA_SUPERAGENT_CONFIG`、
   独立 Inbox、grant 文件、账户和群白名单。保持平台 `send_enabled=false`。
3. 完整重启独立 AstrBot，再打开上述插件视图。输入已有操作者的明文凭据，点击“连接工作区”。
   Dashboard 登录不会代替账户/群能力授权；页面只显示该凭据与配置共同允许的群。
   凭据仅保留在当前页面内存，通过 bridge 的 POST 请求传递；不放入 URL、本地存储或日志。

如果只管理记录，两个 Worker 标志都可关闭；页面仍可建单、审核和安排跟进。
要自动处理队列或到期订阅，仍需独立启用已有 Worker 并配置模型/Worker 凭据。
打开页面不会启动 Worker，也不会调用模型或微信 Hook。

## 日常操作

- **消息建单**：选择群 → 选中已有文本消息 → “从这条消息建单” → 填写处理目标。
  同一来源只能建立一个不可变目标，已有目标可直接打开。非文本消息不支持建单。
- **任务与审核**：选中目标 → “添加任务”。已启用的 Ticket Worker 顺序领取任务，结果进入待审核。
  点击任务查看候选 → “添加证据” → 核对依据后“审核通过” → “保存为草稿”。
  草稿按钮返回持久化草稿编号，不发送微信。证据不足时不能审核通过。
- **定时跟进**：在目标详情中“安排跟进”，按浏览器本地时间选取未来时间。
  到期订阅只产生 Ticket；可在“定时跟进”查看、暂停、恢复或取消。
- **完成目标**：全部 Ticket 完成且没有未解决的订阅后，点击“完成目标”。
- **重新处理**：review 状态可填写原因后重新排队；这会清空旧候选并再次消耗模型调用。
  页面不提供全库恢复、直接领取、自动审核或启用真实发送的入口。

点击“刷新”读取最新状态；切换群时会清除旧选择。更换操作者或审核者时先“断开”，再连接另一凭据。
页面根据已有能力隐藏/禁用不可用操作，后台仍独立鉴权，不能靠修改浏览器请求扩大权限。
现有审核规则检查证据，不强制不同审核者身份；如需职责分离，使用独立 grant 和凭据。

## 展示范围与限制

- 主列表有明确上限：最近 60 条消息、80 个目标、160 项任务摘要、80 条订阅。
  单个目标详情显示最近 60 项任务及 80 条审计记录。搜索只过滤已加载列表，不是全库搜索。
- 消息预览最多显示前 4000 个字符；候选以纯文本显示，消息/模型内容不会作为 HTML 执行。
- 连接只验证配置/凭据；每次业务请求都会重新检查当前实例的绑定平台、账户和数据库。
  未配置、平台已停止、范围不匹配或启用真实发送时拒绝操作。
- 页面不显示 Worker 心跳，不承诺“排队”即正在执行；Worker 是否运行仍以独立实例配置为准。
- 关闭页面、刷新页面或断开即丢弃页面内存凭据。接口只返回业务字段，不返回 claim token。
- 本轮只允许静态核对、Python 语法编译与 JavaScript 语法检查；未编写/修改任何测试代码，
  未运行本地测试、启动实际 AstrBot 或连接微信。原生页面和 bridge 尚需实际实例验收。

这是独立插件的草稿模式原型，不修改已有生产服务。
